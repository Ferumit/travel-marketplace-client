# Туристический маркетплейс — приложение туриста

Flutter-приложение (Android и iOS) для путешествий по Казахстану: турист находит гида и водителя, собирает маршрут на карте, бронирует поездку, переписывается с командой, а в горах без связи может подать SOS по Bluetooth-mesh.

Здесь же лежит серверная часть платформы — Cloud Functions и правила Firestore. Приложение для гидов и водителей — в [travel-marketplace-partners](https://github.com/Ferumit/travel-marketplace-partners), сайт — в [travel-marketplace-web](https://github.com/Ferumit/travel-marketplace-web).

**Стек:** Flutter (Dart 3.11), go_router, Firebase (Auth, Firestore, Storage, Cloud Functions, Messaging, Crashlytics, App Check), Yandex MapKit, Bridgefy (BLE-mesh).

## Что здесь интересного

**SOS с запасным путём.** Сигнал уходит по Bluetooth-mesh и, когда есть сеть, записывается в Firestore; без сети он ждёт в очереди (SharedPreferences) и уходит, когда связь вернулась. Любое устройство сети, принявшее сигнал по Bluetooth, ретранслирует его в облако, а дубли отсекаются детерминированным идентификатором сигнала (UUID v5). Транспорт — синглтон с явным `reset`, а `start` дожидается подтверждения SDK через `Completer`: так убрана гонка, при которой код считал Bluetooth включённым раньше, чем SDK об этом сообщал.

**Рация и чат без интернета.** Голосовые сообщения режутся на фрагменты по 380 байт — с запасом под размер BLE-пакета — и собираются на приёмной стороне с таймаутом 60 секунд. Экран «WAVE» сделан по образцу Zello: история, кнопка push-to-talk, ближайшие участники с расстоянием. Firestore здесь не участвует: Firebase Auth нужен только затем, чтобы узнать, кто ты.

**Маршрут с запасным вариантом.** Путь строится через Yandex MapKit Driving API по точкам и шагам; если сервис недоступен или вернул ошибку, конструктор не падает, а переключается на прямые линии (формула Haversine) и считает расстояния сам.

**Платёжный контур на Freedom Pay.** `initFreedomPayment` создаёт платёж и отдаёт ссылку; приложение открывает её во встроенном WebView и следит за документом платежа в Firestore. Уведомление провайдера принимает `freedomPaymentCallback` — с проверкой подписи и подписанным ответом. Выплата партнёрам делится на две части — при старте поездки и при её завершении — и пишется одной пакетной записью, а флаги `firstPayoutDone` / `secondPayoutDone` защищают от повторного срабатывания триггера. Вывод средств выполняется транзакцией по балансу партнёра. Контур собран в тестовом режиме: страница оплаты — mock для эмулятора, реальный вызов выплаты не подключён.

**Серверные триггеры.** Новое сообщение в чате поездки и смена её статуса превращаются в push всем участникам, кроме отправителя. Раз в сутки по расписанию удаляются аккаунты, помеченные на удаление больше 30 дней назад, вместе с их бронированиями.

**Правила доступа вместо доверия клиенту.** По умолчанию всё запрещено; бронирование и отзыв создаются только от своего имени, документы платежей пишет только сервер.

**Наблюдаемость.** Ошибки Flutter и асинхронные ошибки уходят в Crashlytics (в отладке выключено), App Check активируется с обработкой таймаута и сбоя — приложение не зависает на старте.

## Что не доделано

- Тесты: один smoke-тест на приложение, остальное проверялось руками.
- SOS: серверной обработки сигналов нет — рассылка спасателям и ближайшим партнёрам по коллекции `sos_signals` не реализована.
- Платежи работают в тестовом режиме, реальная выплата не подключена.

## Что убрано из этой копии

Репозиторий — публичная копия рабочего проекта. Из него вырезаны данные заказчика и всё чувствительное: контакты и домены, идентификаторы проекта Firebase и ключи сервисов (карты, Bluetooth-mesh, платёжный провайдер), адреса серверов и настройки деплоя, служебные скрипты, работавшие с реальными данными, внутренние материалы. Ключи подписи приложений и файлы окружения в репозиторий никогда не попадали — они под `.gitignore`.

История коммитов не переносилась намеренно: один коммит вместо неё, чтобы ничто не уехало прошлым. Поэтому проект **не собирается как есть** — нужны свои:

- `android/app/google-services.json` и `ios/Runner/GoogleService-Info.plist` (рядом лежат файлы `.example`) и значения в `lib/firebase_options.dart` (`flutterfire configure`);
- `.env` из `.env.example` и `dart run build_runner build` — он сгенерирует `lib/env/env.g.dart`;
- ключи Yandex MapKit и Bridgefy — места замены помечены `YOUR_YANDEX_MAPKIT_API_KEY` и `YOUR_BRIDGEFY_API_KEY`;
- Android SDK Bridgefy: он лежал в `android/local_repo/` и в копию не входит;
- `functions/.env` из `functions/.env.example` — доступы к почте и платёжному провайдеру.

Права на код принадлежат заказчику. Выложено как портфолио.
